# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Bioinformatics workflows for molecular QTL (mQTL) analysis in the All of Us (AoU) cohort. WDL workflows registered for Dockstore, run on Cromwell/Terra.

## Architecture

### Overall Organization
- workflows/ contains any WDLs that will be used for pipelines, subfolders and utility WDL files are allowed
- scripts/ contains any scripts that will be used within custom environments for pipelines, every dockerfile should copy the entire scripts/ folder
- envs/ contain Dockerfiles for custom environments used in workflows, named flat as `Dockerfile.<env-name>` (not one Dockerfile per subfolder)
- ref/ contains static reference/annotation data files checked into the repo (not generated by a workflow task) for use as workflow inputs — see `ref/README.md`

All envs should have their own rule in .github/workflows so that they will be updated whenever the relevant dockerfile or any of scripts/* is changed.
All workflows should be registered in .dockstore.yml.

### 1. VCFToPlink (`workflows/vcf_to_plink.wdl`)

Converts a VCF into a PLINK2 fileset (`.pgen`/`.pvar`/`.psam`), applying standard QC filters.

- Single task (`Plink2MakePgen`) runs `plink2 --vcf ... --maf ~{MinAF} --hwe ~{HWEPvalThreshold} --make-pgen` inside the `bioinformatics` Docker image.
- `MinAF` (default `0.01`) drops variants below that minor allele frequency; `HWEPvalThreshold` (default `0.000001`) drops variants failing the Hardy-Weinberg exact test at that p-value. (Written as a plain decimal rather than `1e-6`: Dockstore's WDL parser rejects scientific-notation float literals.)
- Docker image is built from **this repo** (`envs/Dockerfile.bioinformatics`) and published to Docker Hub as `<DOCKERHUB_USERNAME>/aou_meqtl-bioinformatics` (CI lowercases the repo name — `AoU_meQTL` — since Docker Hub image names must be lowercase). The WDL selects the tag via the `ImageTag` input (defaults to `latest`; pass a 7-char commit SHA to pin a specific build).

### 2. BinCpGMethylation / BinCpGMethylationCustomBins (`workflows/bin_cpg_methylation*.wdl` + `workflows/utils/cpg_methylation_tasks.wdl`)

Bins per-CpG methylation calls (a pb-CpG-tools bed) into genomic bins and summarizes each bin. Both workflows share the same tasks from `utils/cpg_methylation_tasks.wdl`; they differ only in how the bins bed is produced:

- **BinCpGMethylation** (`workflows/bin_cpg_methylation.wdl`) takes `ChromSizes` + `WindowSize` and calls `MakeWindows` (`bedtools makewindows -g ~{ChromSizes} -w ~{WindowSize}`) to build fixed-size bins covering the whole genome.
- **BinCpGMethylationCustomBins** (`workflows/bin_cpg_methylation_custom_bins.wdl`) instead takes a user-supplied `BinsBed` directly (e.g. gene bodies, CpG islands, arbitrary regions) and skips `MakeWindows`.
- Both then call `BinCpGs`, which aggregates per bin using `bedtools map` (no custom script): it appends an integer-coverage column and a `methylation * coverage` column to `CpGBed` via `awk`, then runs `bedtools map -a <named BinsBed> -b <annotated CpGBed> -c <meth>,<meth>,<cov>,<weight> -o count,mean,sum,sum` to get `num_cpgs`, `unweighted_mean_methylation` (bedtools' `mean` op), `total_coverage`, and a weighted-sum column in one native pass; a final `awk` divides the weighted sum by `total_coverage` to get `weighted_mean_methylation` and drops bins where `bedtools map`'s `count` column is `0` (empty bins are dropped rather than emitted with NAs — note `count` is literally `0` for empty bins, not `.` like the other columns).
- `BinCpGs` requires every bin to have a name in column 4, since that's carried through to the output's `name` column: if `BinsBed` is a plain 3-column bed (e.g. `MakeWindows`'s output, which has no name column), it synthesizes one per bin from the interval itself (1-based inclusive, samtools/tabix style, e.g. `chr1:1-50000`) before the `bedtools map` call; if `BinsBed` already has a 4th column (e.g. `ref/functional_regions.hg38.bed.gz`'s `region_type`), that's kept as-is instead.
- `CpGBed` and `BinsBed` (the latter only in `BinCpGMethylationCustomBins`, since `BinCpGMethylation`'s comes from `MakeWindows`, which never gzips its output) may each be gzip-compressed or plain text — both workflows check each one's filename for a `.gz` suffix (`basename(File) != sub(basename(File), "\\.gz$", "")`, the standard WDL idiom for a suffix test) and, if present, run it through the `Unzip` task (a plain `zcat`) before passing it on to `IntersectWithIntervals`/`BinCpGs`, which otherwise assume plain text (neither `awk` nor `head` can read gzip directly the way `bedtools intersect`/`map` can for file arguments passed straight through). `Unzip` only ever runs on confirmed `.gz` input, so it doesn't need to guess at a particular `zcat`'s passthrough behavior for plain text (the bedtools image's `zcat` is BusyBox's, which — unlike GNU gzip's — refuses to pass already-plain-text input through, erroring `zcat: no gzip/bzip2/xz magic`); `Unzip` itself uses `debian:bookworm-slim` rather than the bedtools image, since it only needs `gzip`/`cat`.
- Both workflows have an optional first task (`IntersectWithIntervals`): if `IntervalBed` or `IntervalString` is given, restricts `CpGBed` to those regions via `bedtools intersect -u` before binning (`IntervalBed` takes precedence if both are set). `IntervalString` accepts either a 1-based inclusive region, e.g. `chr1:1000000-2000000` (samtools/tabix style, converted to 0-based BED internally), or a bare chromosome name, e.g. `chr18` (matched by presence/absence of `:`).
- `MethCol`/`CovCol` (defaults `4`/`6`) are 1-based column indices into `CpGBed`, assuming the standard pb-CpG-tools combined pileup bed (`chrom, start, end, modification_probability, haplotype, coverage`). Adjust these if the input bed has a different layout (e.g. "count" mode, which adds modified/unmodified count columns).
- `ChromSizes` (BinCpGMethylation only) is a standard 2-column `chrom<TAB>size` file (as produced by `cut -f1,2 ref.fa.fai` or UCSC `chrom.sizes`).
- Output bed has a `#`-prefixed header and is sorted by `chrom,start`.
- Docker image: the public `quay.io/biocontainers/bedtools` image (not `envs/Dockerfile.bioinformatics`) — these tasks only need `bedtools`/`awk`/`sort`, all present in that image, so there's no need to build/push a custom image or wait on this repo's CI. Tag is set per-task via the `DockerImage` input (default `quay.io/biocontainers/bedtools:2.31.1--h13024bc_3`), threaded down from the `DockerImage` workflow input. The one exception is `Unzip`, which defaults to `debian:bookworm-slim` instead (same base as `envs/Dockerfile.bioinformatics`) since it only needs `gzip`/`cat` — the workflows don't thread `DockerImage` into its calls, so it keeps that default rather than pulling in bedtools for no reason.

### 3. Functional regions resource (`ref/functional_regions.hg38.bed.gz`)

A pre-built, checked-in bed of functional regions (enhancers/promoters, gene bodies, CpG islands), intended as the `BinsBed` input to **BinCpGMethylationCustomBins**. See `ref/README.md` for what it contains and how to regenerate it (`ref/build_functional_regions_bed.sh`).

### 4. BuildBedMatrix (`workflows/build_bed_matrix.wdl` + `workflows/utils/bed_matrix_tasks.wdl`)

Turns N per-sample bed files (e.g. per-sample `BinCpGMethylation`/`BinCpGMethylationCustomBins` output) into a single wide bed matrix — `chrom, start, end, feature`, then one value column per sample — i.e. a QTL-mapping phenotype bed. Generic: doesn't assume any particular input bed layout beyond "has a feature-ID column and a value column somewhere".

- Inputs: `BedFiles` (`Array[File]`) and `SampleIDs` (`Array[String]`), same length/order — `SampleIDs[i]` becomes the output column header for `BedFiles[i]`'s value column. `FeatureCol`/`ValueCol` are 1-based column indices into each bed: whatever's in `FeatureCol` is renamed `feature` in the output (regardless of its original column name/position), and whatever's in `ValueCol` becomes that sample's value column.
- Batched to avoid joining arbitrarily many samples in one task: the workflow splits `BedFiles`/`SampleIDs` into chunks of `BatchSize` (default `50`) using a nested `scatter`/`select_all` directly in WDL (`BedFiles[i]`/`SampleIDs[i]`, filtered by batch-index range), then scatters `BuildMatrixBatch` over those chunks (one wide matrix per batch), then `JoinMatrices` combines the per-batch matrices into the final one. This is **not** done via a task that writes `BedFiles`' paths into a manifest for a later task to read back as new `File` values (an earlier version did this, via a `MakeBatches` task + `split -l`) — a task only sees each `File`'s *localized* path inside its own sandbox, not a portable reference, so round-tripping that path through a file and re-coercing it downstream works on a local backend (shared filesystem) but breaks on Cromwell/Terra's GCP backend, where each task localizes inputs into its own container (surfaces as e.g. a `size()`/`auto_disk_size` evaluation failure with two GCS paths nonsensically concatenated together). Indexing the original arrays directly always keeps the tracked `File` reference intact.
- Both the per-sample-to-batch-matrix join (`BuildMatrixBatch`) and the batch-matrix-to-final join (`JoinMatrices`) key on `chrom:start:end` (not on the feature column, since feature values aren't guaranteed unique — e.g. `ref/functional_regions.hg38.bed.gz`'s `region_type` repeats across many rows) via repeated two-file `join` calls (no single command joins >2 files). This is an **inner join**: a region missing from any one sample (or any one batch) is dropped from the final matrix entirely rather than padded with NA — there's no outer-join/fill-missing option.
- `Bgzip` (default `true`) bgzip-compresses the final matrix (`JoinMatrices` runtime's `quay.io/biocontainers/tabix:0.2.6--ha92aebf_0` — the legacy standalone tabix/bgzip package, not full htslib, kept lightweight since this only needs `awk`/`sort`/`join`/`bgzip`); the other two tasks use plain `debian:bookworm-slim` for the same reason.
- Doesn't handle gzip-compressed input `BedFiles` (unlike `BinCpGMethylation*`'s `Unzip` pattern) — feed in plain-text beds.

### 5. CpGSummaryStats (`workflows/cpg_summary_stats.wdl` + `workflows/utils/cpg_summary_stats_tasks.wdl`)

Computes, per CpG, the mean and variance of a value column across N per-sample pb-CpG-tools combined pileup beds (`chrom, start, end, modification_probability, haplotype, coverage`) — for when you just need summary stats across samples rather than a QTL-mapping phenotype matrix, and building a full `BuildBedMatrix`-style wide matrix would be too much data to materialize.

- Never joins samples into a wide matrix. Instead folds samples down to the additive sufficient statistics for variance — count (`n`), sum, and sum-of-squares — in two reduction passes, each a `sort` + `awk` group-by-CpG-key (`chrom:start:end`) rather than `BuildBedMatrix`'s `join`-based fold: the workflow splits `BedFiles` into chunks of `BatchSize` (default `50`, same nested-`scatter`/`select_all` WDL-native batching as `BuildBedMatrix` — see its entry above for why this isn't done via a manifest-writing task), scatters `ComputeBatchStats` over those chunks (reduces each chunk to one `n`/`sum`/`sumsq` row per CpG), then `CombineStats` sums those same per-CpG statistics across all batches and converts the totals to `mean` and sample variance (`(sumsq - sum^2/n) / (n-1)`, Bessel's corrected). Every intermediate file has at most one row per CpG, never one column per sample, so disk/memory use doesn't scale with sample count the way a full matrix would.
- Unlike `BuildBedMatrix`'s inner join, a CpG missing from some samples isn't dropped or padded with NA — it's simply computed from however many samples actually had it (`n` varies per CpG). A CpG seen in only one sample (`n=1`) gets a `mean` but no `variance` (`NA`, since the denominator would be zero).
- A CpG's identity is just its `chrom:start:end` coordinate — unlike `BuildBedMatrix` there's no separate feature-name input column; the output's `name` column is synthesized from the coordinate itself (1-based inclusive, samtools/tabix style, same convention `BinCpGs` uses, e.g. `chr1:12346-12346`). `ValueCol` (1-based column index into each bed, default `4`) is the only column selector: `4` is `modification_probability` (methylation) in the standard pb-CpG-tools layout; pass `6` (`coverage`) instead to get variance of coverage rather than methylation. Rows where the value column is `NA` are skipped rather than corrupting the sums.
- Output bed has a `#`-prefixed header (`chrom, start, end, name, n, mean, variance`), sorted by `chrom,start`, optionally bgzipped (`Bgzip`, default `true`).
- Uses the naive two-pass-equivalent sum/sum-of-squares formula for variance, not a numerically-stabilized one (e.g. Welford's) — fine given methylation values are bounded in `[0,1]` or `[0,100]`, but worth revisiting if this is ever reused for unbounded values at very large sample counts.
- Doesn't handle gzip-compressed input `BedFiles`, same as `BuildBedMatrix` — feed in plain-text beds.
- Docker images: `debian:bookworm-slim` for `ComputeBatchStats` (only needs `awk`/`sort`), `quay.io/biocontainers/tabix:0.2.6--ha92aebf_0` for `CombineStats` (adds `bgzip`) — same choices as `BuildBedMatrix`'s equivalent tasks, no custom image needed.

### 6. BuildFilteredCpGMatrix (`workflows/build_filtered_cpg_matrix.wdl` + `workflows/utils/cpg_bin_filter_tasks.wdl`)

End-to-end pipeline from raw per-sample pb-CpG-tools beds to a QC-filtered QTL-mapping phenotype matrix, composed entirely from tasks already used by `BinCpGMethylation*`, `CpGSummaryStats`, and `BuildBedMatrix` plus one new tasks file for the per-bin stats/filtering step:

1. **Bin**: scatters `BinCpGs` (from `cpg_methylation_tasks.wdl`) over every sample's `CpGBeds`, into either `BinsBed` (if given — preferred) or fixed-size windows built from `ChromSizes`+`WindowSize` via `MakeWindows` — the same choice `BinCpGMethylation` vs. `BinCpGMethylationCustomBins` make as two separate workflows, merged here into one `if (defined(BinsBed))` branch. Both `BinsBed` and each sample's `CpGBed` are gz-detected and decompressed (`Unzip`) the same way those two workflows already do.
2. **Summarize**: folds the per-sample binned beds down to one row per bin — `mean_value`/`variance_value`/`min_value`/`max_value`/`delta` (`max_value - min_value`) of `ValueCol` (default `8` = `unweighted_mean_methylation`), `mean_num_cpgs` (mean of `num_cpgs`), and `presence` (`n / TotalSamples`) — via the same batched running-total reduction as `CpGSummaryStats`, just also tracking a running min/max alongside the count/sum/sum-of-squares (`ComputeBinStatsBatch` then `CombineBinStats`, in the new `cpg_bin_filter_tasks.wdl`), so this step never joins samples into a wide matrix either. A bin missing from some samples isn't dropped — `n`/`presence` just reflect however many samples actually had it.
3. **Filter**: `FilterBins` labels every bin `PASS`/`FAIL` against four thresholds — `MinPresence` (default `0.8`), `MinMeanCpGs` (default `3.0`), `MinVariance` (default `0.001`), `MinDelta` (default `0.1`) — and emits both the full per-bin stats bed (all bins, with the `filter` column) and a bed of just the `PASS` bins' coordinates. `MinVariance` and `MinDelta` both guard against bins with no meaningful variability to test for association, from two angles: variance is sensitive to the overall spread (and to a few outlier samples), while delta is just the raw range (`max - min`) — a commonly cited minimum "meaningfully different" methylation range in the DNAm literature is roughly `0.05`-`0.1` on a 0-1 scale. These are starting points from common region-level methylation/mQTL phenotype-filtering practice, not hard literature standards — tune per cohort/tissue. A bin with `n <= 1` has no variance (`NA`) and automatically fails. All four are plain decimals (not `0.0001`-style scientific notation), per the same Dockstore WDL-parser float-literal gotcha as `VCFToPlink`'s `HWEPvalThreshold`.
4. **Filter-then-matrix**: `FilterBedToPassingBins` restricts each sample's binned bed to only `PASS` bins (a two-file `awk` filter keyed on `chrom:start:end`) *before* matrix-building — not after — so `BuildMatrixBatch`/`JoinMatrices`'s per-sample joins (reused as-is from `BuildBedMatrix`) never have to consider a bin that would be dropped anyway. Same inner-join caveat as `BuildBedMatrix` applies on top of this: a `PASS` bin missing from one particular sample's filtered bed is still dropped from the final matrix for all samples, not padded with NA.
5. Batching (bin-stats step and matrix step both) uses the same WDL-native nested-`scatter`/`select_all` pattern as `BuildBedMatrix`/`CpGSummaryStats`, not a manifest-writing task — see `BuildBedMatrix`'s entry above for why.
- Outputs: `Matrix` (the final filtered phenotype matrix, same shape as `BuildBedMatrix`'s output) and `SummaryStats` (the full per-bin stats bed for every bin considered, `PASS` and `FAIL` alike — useful for diagnosing/tuning the filter thresholds, not just consuming the matrix).
- `MethCol`/`CovCol` (defaults `4`/`6`) thread through to `BinCpGs` same as in `BinCpGMethylation*`. `FeatureCol` isn't exposed as a workflow input (unlike `BuildBedMatrix`) — it's hardcoded to `4` (`name`) since every bed flowing into the matrix step here is always `BinCpGs`-shaped, not an arbitrary bed.

## Common Commands

There is no build/test/lint tooling in this repo — it is WDL + a Dockerfile.

Build the bioinformatics Docker image locally (note: Docker context is repo root, Dockerfile path is explicit):
```
docker build -f envs/Dockerfile.bioinformatics -t aou-mqtl-analysis .
```

Validate / run WDLs locally (requires miniwdl or womtool/cromwell, not vendored):
```
miniwdl check workflows/vcf_to_plink.wdl
```

## CI

`.github/workflows/bioinformatics-docker-image.yml` builds and pushes the bioinformatics image to Docker Hub on push/PR to `main`/`develop`, when `scripts/**` or `envs/Dockerfile.bioinformatics` changes. Images are named `<DOCKERHUB_USERNAME>/aou_meqtl-bioinformatics` and tagged `latest` + the 7-char commit SHA. Auth uses the `DOCKERHUB_USERNAME` repo **variable** and the `DOCKERHUB_TOKEN` **secret**.

## Gotchas

- `plink2` has no Debian package, so the Dockerfile pulls the prebuilt binary from cog-genomics' `_latest` S3 alias. Pin `PLINK2_VERSION` (build arg) to a dated build instead for a reproducible image.
- `--maf`/`--hwe` in plink2 apply across the whole sample by default. If case/control-aware HWE filtering is ever needed (only filtering on controls), that requires `--hwe ... midp` semantics or splitting by phenotype first — not currently implemented.
- The repo name (`AoU_meQTL`) has uppercase letters, but Docker Hub image names must be lowercase — the CI workflow lowercases `REPO_NAME` before building the tag. The hardcoded Docker image string in `vcf_to_plink.wdl` (`ayenkin1871/aou_meqtl-bioinformatics`) must be kept in sync with whatever that lowercased name resolves to; update both if the repo is renamed or forked under a different Docker Hub account.
- Don't batch an `Array[File]` by having a task write the files' paths into a manifest for a later task/scatter to read back as new `File` values (e.g. `read_lines`/`read_tsv` + implicit `String`→`File` coercion) — works fine with miniwdl or Cromwell's local backend (shared filesystem), but breaks on Cromwell/Terra's GCP backend, where each task localizes `File` inputs into its own container at a path specific to that task's execution, not a portable reference. `BuildBedMatrix`/`CpGSummaryStats` batch via a nested `scatter`/`select_all` over `range(NumBatches)`/`range(NumSamples)` instead (indexing `BedFiles[i]` directly keeps the original tracked reference) — the tradeoff is this is O(`NumBatches` × `NumSamples`) scatter shards (all pure value-selection, no actual task execution, so cheap per-shard, but still something to revisit — e.g. WDL 1.1+'s `as_map`/better array ops, or just accepting pre-batched `Array[Array[File]]` input — if sample counts ever get very large).
